# 制作ワークフロー

## 制作するものと現在地

1976年前後の新宿・歌舞伎町を、一番街入口から旧コマ劇場前まで、実際に歩いて長回し撮影したようなカラー映像にする。地区・年代ごとの3D空間、アセット、カメラ動線を残し、昭和の東京の別地区へ拡張する。

第1ラウンドで現代のPLATEAU街区と、航空写真を参照した配置仮説・経路候補を作成した。[現在の成果と制約](DATA_INTAKE_R01.md)を参照。歴史的な門・劇場正面・経路中間は未確定で、歴史考証の合格と最終的な画づくりの承認はまだない。以下は制作全体の順序を示す。

Leon Linの投稿と[Cook Loop](https://github.com/Leonxlnx/cook)を参考に、強いリファレンス、静止画先行、独立した批評、問題箇所を指定した反復を採用する。成果で区切って進め、作業時間や自己採点を完成の証拠にしない。

## リファレンスの役割

| 種類 | 判断に使うもの | 記録すること |
| --- | --- | --- |
| 当時の実写・地図・航空写真 | 建物の同定、道順、形状、看板、時代 | 原典、撮影年と推定根拠、視点、確認できる範囲、利用条件 |
| 現代のPLATEAU・OpenStreetMap | 位置関係・道路接続・地理座標の下敷き | 選択したデータ、整備年・取得日、範囲、座標系、加工手順 |
| 承認済みのカラー参考画9枚 | 光、色、素材感、現代のカメラでそこに立ったような見え方 | 対応する原資料、年代差、推定した色や形、採用する要素 |

既存資料には1971〜1978年などの年代差がある。9枚を1976年の連続した街並みと認定せず、各画像を原資料と照合する。ミラノ座と旧コマ劇場の資料は建物ごとに区別し、コマ劇場正面と経路中間の不足資料を優先して補う。

各地点に「実写・地図の証拠」「カラー参考画」「今回のレンダー」を対応づける。史実の比較と見た目の比較を別に記録する。撮影位置や時代が違う画像同士から、単純な画素一致率で正確さを認定しない。白黒資料からの色は推定と明記し、完成映像はフルカラーを基準とする。

## 制作の順番と完了条件

| 段階 | 提出物 | 次へ進む条件 |
| --- | --- | --- |
| 1. 出典と街区の下敷き | 資料対応表、選択データの台帳、切り出し・変換手順、現代の基礎GLB、俯瞰ルート案 | 出典・年代・利用条件・座標系が追える。現代データと歴史復元を区別し、経路の未確認箇所が見える |
| 2. 歩ける街区骨格 | 地面・建物の簡略モデル、歴史資料に基づく置換、共通カメラ経路、6地点の固定カメラ | 同じ縮尺で入口から劇場まで通れる。主経路・門・劇場の同定に重大な矛盾がなく、確認できない形状は明示されている |
| 3. 入口の一角を仕上げる | 約15〜20mを目安にした高品質な一角、近景と遠景の静止画、短いカメラ移動テスト | 窓・庇・看板・店内に移動しても保たれる奥行きがある。照明と素材がカラー目標に届き、全体へ展開できる制作方法ができている |
| 4. 6視点の静止画 | 下表の6枚、実写との比較、カラー目標との比較、批評と修正記録 | 歴史・地理と映像表現の両方で重大な問題を解消。ユーザーが画づくりを確認する |
| 5. 入口15秒の試写 | 1920×1080・30fpsを目標にした450フレームの試作、コンタクトシート、環境音の試聴 | 看板・建物・人物・遮蔽・露出・歩行が連続する。ユーザーが歩行感と画質の方向を確認する |
| 6. 全経路と最終出力 | 30〜60秒の検証版、実距離に合わせた全経路版、最終4K映像、音響・クレジット | 経路全体で重大な問題を解消。承認した画づくり・動きと予算内で最終レンダーし、書き出した映像と音声を検品する |

段階1〜2では、未確認部分を含む仮モデルで検討を進めてよい。ただし主経路や劇場の同定に根拠不足が残る間は、歴史考証の合格とはしない。周辺の見えない部分まで一律に作り込まず、カメラに映る範囲と反射・影に影響する範囲から仕上げる。

### 6地点の固定カメラ

地点IDは[シーン定義](../scenes/shinjuku/kabukicho/1976/scene.json)と対応する。並びは制作上の確認順であり、座標や曲がり方を検証済みとするものではない。

| 地点ID | 見せるもの | 特に確認すること |
| --- | --- | --- |
| `entrance-approach` | 一番街入口の手前 | 門の年代、入口の幅、周囲の建物 |
| `under-gate` | 門をくぐる位置 | 門の裏面、看板の厚み、近景の視差 |
| `ichibangai-middle` | 一番街の中ほど | 店舗の連なり、奥行き、遠くの細部 |
| `towards-koma-corner` | 劇場へ向かう曲がり角 | 曲がる前後の接続、見通し、建物の同一性 |
| `plaza-reveal` | 劇場前広場が開ける位置 | 道から広場へのつながり、劇場の向き |
| `koma-front` | 旧コマ劇場の正面 | 建物の同定、外観、入口、当時の掲示物 |

## 共通の制作基盤

地理データの切り出しと座標変換をスクリプト化し、Blenderを制作・最終レンダー、GLBを交換形式、Three.jsを軽い歩行・見通し確認に使う構成を基本とする。実際に使うバージョン、書き出し設定、依存関係は最初の変換テストで固定する。

- シーン交換はメートル単位・右手系Y-up。地理原点、元の座標系、変換を別途保持し、Blenderとの軸変換を検査する。
- 建物ID、看板ID、アセット版、固定カメラ、共通の時間軸を維持する。外観の修正で道順や建物配置を勝手に変えない。
- 高さ1.6m、35mm相当、通常歩行約1m/sを初期案とする。停止・振り向き・減速はカメラ計画に記録し、本編の尺は確認した経路長から決める。
- 季節・時刻・天候・露出・色管理は段階3で比較し、段階4の承認条件として固定する。「雨上がりの夕刻」等は候補であり、史実として扱わない。
- 元の制作データから同じシーンを再現できるようにする。人物や車両は、時代・接地・移動・遮蔽を検証できる範囲から増やす。
- 生成AIによる仕上げを使う場合も、建物の形、読める文字、人物の同一性、カメラ動線を維持する。区間分割する場合は同じ世界と時間軸の重複区間で接続を検査する。
- 外部のOSS・オープンデータ・利用可能な素材を活用する。各アセットの出典・再配布条件は[アセット方針](ASSET_POLICY.md)に従い記録する。

## 反復のしかた

各ラウンドは、次の順に実施する。ログは[ラウンド記録テンプレート](templates/ROUND_REPORT.md)を使い、`docs/rounds/`に残す。まだ実施していない検査は「未実施」、測定していない値は「未測定」と書く。

1. **比較条件を固定する。** 元コミット、対象シーン、カメラ、資料IDと年代、出力設定、時間・費用の上限を記録する。利用可能ならモデル・ツール版、プロンプト、シードも残す。
2. **修正対象を1〜3件に絞る。** ユーザーの具体的な指摘を優先し、次に最も重大な問題を選ぶ。例えば「曲がり角で劇場が早く見えすぎる」「入口看板の字が変わる」のように対象と場所を指定する。
3. **局所的に直してレンダーする。** 同じカメラの静止画、比較画像、必要な短い動画を作る。良くなった部分は維持する。
4. **比較・測定する。** 構図、光、色、素材、近景と遠景の密度を確認する。動画は通常速度の再生とコンタクトシートで経路全体を見て、疑わしい区間をコマ単位で調べる。フレーム差分等の自動検出は候補抽出として使い、人の目による確認を置き換えない。
5. **独立した批評を受ける。** 制作側の説明や自己採点を渡さず、[批評依頼テンプレート](templates/CRITIC_BRIEF.md)で新しい文脈の批評担当を使う。歴史・地理と、映像・動き・音の2系統で、画像領域またはタイムコード付きの指摘を得る。
6. **修正・継続・資料調査を決める。** 致命的・重大な問題を解消してから段階を進める。資料不足なら調査に戻り、生成の反復だけで正しさを認定しない。
7. **結果を共有し記録する。** 比較画像、直した点、残る問題、次の修正対象を示す。承認を待つ間も、資料整理や別箇所の修正、数フレームのレンダーテストは続ける。

## 品質の判定基準

| 分野 | 合格の判断 | 検査方法 |
| --- | --- | --- |
| 歴史・地理 | 主経路、門、劇場の同定・年代・向きに重大な矛盾がない | 原典への対応表、俯瞰図、実写との比較。推定箇所と反証を併記する |
| 縮尺 | 根拠のある寸法とモデルが対応する | 資料の測定精度を記録し、測れる箇所のみ誤差を測る。十分な精度がある箇所は差5%以内を初期目安にする |
| 見た目 | 6視点すべてで光・色・素材・密度が目標に達する | 同じ構図の比較、近景と遠景の拡大。過度な発光、色被り、ぼかしで形状不足を隠さない |
| 空間の連続性 | 建物・看板・路面が突然変形・出現・消失しない | 共通の世界座標、固定カメラ、通常再生、曲がり角と遮蔽前後の重点検査 |
| 文字・人物・車 | 読める看板が変わらず、目立つ接地破綻・すり抜け・服装や同一性の不連続がない | 近景拡大、遮蔽前後と問題区間のコマ確認 |
| カメラ・時間 | 意図しない速度・露出・照明の急変、点滅、重複・欠落フレームがない | カメラ曲線とフレーム数の検査、通常再生とフレーム間の確認 |
| 音・出力 | 音の位置と距離が自然で、意図しない音割れ・無音・同期ずれがない。指定の解像度・fps・尺で再生できる | ファイル情報の検査、全編再生、ヘッドホン試聴、音源の出典確認 |

「致命的」は経路や建物の取り違え、再生不能など目標を崩す問題。「重大」は通常の視聴で気づく破綻。「軽微」は拡大すると分かる局所的な差。批評結果は合格・要修正・資料不足に分け、根拠不足を合格へ丸めない。資料がない背景の細部は、推定として残せるか、画面の重要度に応じて判断する。

見た目の主観評価と、寸法・フレーム数等の実測値は分ける。9.2/10等のスコアは補助的に使えても、史実の一致率や重大な欠陥の不在を証明しない。「99%正確」とは認定しない。

## 進捗・費用・確認の節目

- 最低8時間などの待機時間を完成条件にしない。初期の作業単位は60〜90分を目安に区切り、成果・問題・実際の所要時間を記録する。長いレンダーは先に数フレームで速度と費用を測る。
- 比較候補は最初は最大3案を目安にし、採用案を深く直す。各ラウンドの生成回数、使用ツール、実費または未確定額、残予算を記録する。利用枠を使い切ること自体を目標にしない。
- 有料APIや外部GPUの予算は未設定。費用が発生する処理の前に、小さな測定結果から必要量と見積もりを具体化する。予算待ちでも、既に認められた資料調査やローカル作業は進める。
- ユーザーがまとめて判断する節目は、6視点の画づくりと15秒試写の歩行感。既存の承認を引き継ぎ、同じ条件を繰り返し確認しない。承認前に長時間・高額な最終出力を始めない。
- GitHubへの制作データ・手順の蓄積は継続する。映像のSNS投稿や外部公開は、制作完了と区別する。

## 最初のラウンドと次の作業

最初の作業単位**「出典付きの街区骨格と俯瞰ルート案」**の成果を[第1ラウンド](DATA_INTAKE_R01.md)へ記録した。次は門・劇場正面・経路中間の不足資料を補い、仮の街区から当時の形状へ置き換える。以下は初回取り込みの手順として維持する。

1. 承認済み9枚と原資料を対応づけ、6地点のどこを裏付けるか、不足は何かを整理する。とくに旧コマ劇場の正面と経路中間を確認する。
2. 対象範囲を覆うPLATEAUとOSMの具体的なデータを選び、[出典台帳](../data/sources.json)にID・年代・範囲・取得日・利用条件を追記する。
3. 必要な範囲を切り出してメートル単位のローカル座標へ変換し、取得・加工手順とSHA-256を残す。地理参照の値は確認できたものだけシーンへ記入する。
4. 現代の下敷きGLBと俯瞰ルート案を出す。歴史資料に照らして残す建物・置き換える建物・未確認の部分を示す。
5. 比較図とラウンド記録を提出し、主経路の確認を進めて段階2の歩ける簡略モデルへ移る。

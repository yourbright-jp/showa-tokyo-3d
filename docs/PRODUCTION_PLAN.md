# 制作ワークフロー

## 制作するものと現在地

1976年前後の新宿・歌舞伎町を、一番街入口から旧コマ劇場前まで、実際に歩いて長回し撮影したようなカラー映像にする。地区・年代ごとの3D空間、アセット、カメラ動線を残し、昭和の東京の別地区へ拡張する。

R01で現代の下敷き、地形、配置仮説、6地点の診断カメラを作成した。R03では「資料で決まらなければ推定してよい」というユーザー指示を受け、門・劇場正面・広場・舗装を具体的な採用値へ進め、全600地物の扱いを分類した。[現在の採用版と再生成手順](RECONSTRUCTION_ADOPTED_1976.md)を参照。採用判断の完了と、史実の全項目の検証・写真品質映像の完成を分ける。以下は制作全体の順序を示す。

R04（2026-11-02〜03）では、R03の採用版を変えずに、three.jsのコード生成で地面・建物・看板・人物・ランドマーク・街路の小物を高精細化した。独立批評を4回、修正を3回行ったが、見た目の合格（映像批評2人がそれぞれ全項目8点以上）には未達。現在地は段階4（6視点の静止画）で、静止画のユーザー承認はまだ。条件は[R04ラウンド条件](rounds/shinjuku-kabukicho-1976-r04-rules.md)、結果と未解決の事項は[R04ラウンド記録](rounds/shinjuku-kabukicho-1976-r04.md)を参照。

Leon Linの投稿と[Cook Loop](https://github.com/Leonxlnx/cook)を参考に、次の進め方を採用する。

- 強いリファレンスを地点ごとに割り当てる。
- 見た目の合格点を数値で決める。
- 静止画をユーザーが承認してから動画を作る。
- 新しい文脈の独立した批評を受ける。
- 問題箇所を指定して反復する。
- すべてをコードで作る。
- スロップを禁止する。

成果で区切って進め、作業時間や自己採点を完成の証拠にしない。

## リファレンスの役割

| 種類 | 判断に使うもの | 記録すること |
| --- | --- | --- |
| 当時の実写・地図・航空写真 | 建物の同定、道順、形状、看板、時代 | 原典、撮影年と推定根拠、視点、確認できる範囲、利用条件 |
| 現代のPLATEAU・OpenStreetMap | 位置関係・道路接続・地理座標の下敷き | 選択したデータ、整備年・取得日、範囲、座標系、加工手順 |
| 承認済みのカラー参考画9枚 | 光、色、素材感、現代のカメラでそこに立ったような見え方 | 対応する原資料、年代差、推定した色や形、採用する要素 |

既存資料には1971〜1978年などの年代差がある。9枚を1976年の連続した街並みと認定せず、各画像を原資料と照合する。ミラノ座と旧コマ劇場の資料は建物ごとに区別し、コマ劇場正面と経路中間の不足資料を優先して補う。

各地点に「実写・地図の証拠」「カラー参考画」「今回のレンダー」を対応づける。史実の比較と見た目の比較を別に記録する。撮影位置や時代が違う画像同士から、単純な画素一致率で正確さを認定しない。白黒資料からの色は推定と明記し、完成映像はフルカラーを基準とする。

r04の決定（2026-11-03）：固定地点`entrance-approach`は門から約10.8mの位置で水平を向き、`under-gate`は門の面の上に立って通りの奥を向く。どちらも35mm相当の画角に門が入らない。R01から続く6地点のカメラ（位置・向き）は比較のため変えず、門を見る役割を補助視点2つ（`r04-gate-establishing`・`r04-gate-rear`）へ移した。両地点の構図は、入口と通過直後の通りの見通しとして評価する。独立批評2件が示した案のうち「構図点の役割を記録し直す」を採った。補助視点は`scripts/make_r04_views.py`で採用値から計算する。

R07（ゴールデン街）は道幅・建物には使わず、古びた質感の参考にとどめる。昼（R01・R02・R08）と夜（R04・R06）の参考画が混在する。季節・時刻・天候は未確定で、段階4の承認時に光の設定として固定する。光の設定は見た目の選択であり、1976年当日の状態を主張しない。r04では作業上の季節を「10月上旬の晴れた午後（14時ごろ）」とした。昼の光の設定（太陽高度40°・方位222°）と、10月1日の冬服への衣替えに合う。人物の服装と街路の飾りをこれにそろえる（1972年写真に見える街路灯の吹き流し・造花と入口の可搬式バリケードは、臨時の物として既定では外す）。段階4のユーザー承認で確定する。

参考画9枚の公開は、2026-11-02にプロジェクトの所有者が確認した。リポジトリは公開とする。ライセンス名は指定されていないため空欄のまま残し、確認内容を各`*.asset.json`の`rights_review`に記録した。第三者の原写真は公開しない。

## 制作の順番と完了条件

| 段階 | 提出物 | 次へ進む条件 |
| --- | --- | --- |
| 1. 出典と街区の下敷き | 資料対応表、選択データの台帳、切り出し・変換手順、現代の基礎GLB、俯瞰ルート案 | 出典・年代・利用条件・座標系が追える。現代データと歴史復元を区別し、経路の未確認箇所が見える |
| 2. 歩ける街区骨格 | 地面・建物の簡略モデル、歴史資料に基づく置換、共通カメラ経路、6地点の固定カメラ | 同じ縮尺で入口から劇場まで通れる。主経路・門・劇場の同定に重大な矛盾がなく、確認できない形状は明示されている |
| 3. 入口の一角を仕上げる | 約15〜20mを目安にした高品質な一角、近景と遠景の静止画、短いカメラ移動テスト | 窓・庇・看板・店内に移動しても保たれる奥行きがある。照明と素材がカラー目標に届き、全体へ展開できる制作方法ができている |
| 4. 6視点の静止画 | 下表の6枚、実写との比較、カラー目標との比較、批評と修正記録 | 歴史・地理と映像表現の両方で重大な問題を解消。ユーザーが画づくりを確認する |
| 5. 入口15秒の試写 | 1920×1080・30fpsを目標にした450フレームの試作、コンタクトシート、環境音の試聴 | 看板・建物・人物・遮蔽・露出・歩行が連続する。ユーザーが歩行感と画質の方向を確認する |
| 6. 全経路と最終出力 | 30〜60秒の検証版、実距離に合わせた全経路版、最終4K映像、音響・クレジット | 経路全体で重大な問題を解消。承認した画づくり・動きと予算内で最終レンダーし、書き出した映像と音声を検品する |

全段階で、確認事実と推定採用を併記した制作モデルを使う。R03で推定を行う権限が明示され（2026-11-02には「わからないところは推測で」と再確認）、資料で決まらない部分も、採用値・根拠・反証・代案を記録して決める。未確定の門や劇場正面を理由に、段階3以降の作り込みを止めない。差し替え可能な代案は、採用判断に記録して残す。採用上の矛盾を解消することと史実を証明することを混同しない。

判定は2つの系統に分け、それぞれ独立に進める。

- **見た目の承認**：画づくりの品質を判定する。段階を進める条件になる。
- **史実の判定**：資料との一致を判定する。新しい資料が見つかれば、採用判断を差し替える。「資料不足」は推定採用として記録し、見た目の承認を止めない。史実の合格へは繰り上げない。

周辺の見えない部分まで一律に作り込まず、カメラに映る範囲と反射・影に影響する範囲から仕上げる。

### 6地点の固定カメラ

地点IDは[シーン定義](../scenes/shinjuku/kabukicho/1976/scene.json)と対応する。R01由来の6地点は固定診断用として保持し、[採用歩行軌道](../scenes/shinjuku/kabukicho/1976/cameras/adopted-walk.json)を別に持つ。並びは制作上の確認順であり、歴史的な座標・入口・正面軸を確認済みとするものではない。地形から各地点の地面高を求め、目線を地上1.6mに置く。広場の範囲と終盤の経路は明示した配置仮説に従い、変更時には6地点を再描画して曲がる前後を検査する。現行E・Fは屋根と広場を同時に確認するため24mm相当、他4地点は35mm相当。採用歩行軌道は35mm相当を固定し、減速・停止・振り向きを時間軸に含める。診断用24mmの画像を、本編の35mm画像と同じ構図とは扱わない。

| 地点ID | 見せるもの | 特に確認すること |
| --- | --- | --- |
| `entrance-approach` | 一番街入口の手前 | 門の柱と入口の幅、周囲の建物、通りの奥行き（門の全景は補助視点`r04-gate-establishing`） |
| `under-gate` | 門をくぐる位置 | 通過直後の見通し、近景の視差（推定補完した裏面と看板の厚みは補助視点`r04-gate-rear`） |
| `ichibangai-middle` | 一番街の中ほど | 店舗の連なり、奥行き、遠くの細部 |
| `towards-koma-corner` | 広場へ向きを変える曲がり角の候補 | 曲がる前後の接続、見通し、建物の同一性 |
| `plaza-reveal` | 広場の開放空間を確認する位置 | 道から広場へのつながり、劇場の向き |
| `koma-front` | 広場から見る採用した旧コマ劇場 | 西側を正面に採った外観と東宝会館の区別。斜めの診断構図と正面軸を区別する |

## 共通の制作基盤

地理データの切り出しと座標変換をスクリプト化する。静止画・試写の正式な描画手段は、**three.js 0.170.0とヘッドレスChromium（SwiftShaderによるCPU WebGL2）**とする（ユーザー承認：2026-11-02）。

- バージョンは`package.json`と`package-lock.json`で固定する。描画は`viewer/`と`scripts/render_stills.mjs`で再現する。
- 手順は`npm ci`、`node scripts/render_stills.mjs`、`python3 scripts/make_comparison.py`。
- この環境は4CPU・GPUなしで、Blenderは入っていない。
- 速度は、各ラウンドで1080pの1地点あたりの秒数を測って記録する。目安は120秒以内。
- 最終4K映像を同じ手段で出せるかは未測定。段階5の試写で1フレームあたりの時間を測り、予算内に収まらなければ代替（Blender Cycles CPU、外部GPUなど）を見積もってから選ぶ。
- Blenderなど別の描画手段を使う場合は、導入手順・版・ハッシュをリポジトリに記録し、再現できる形でだけ使う。
- GLB・glTFは、データの交換と記録用の形式として扱う。

- シーン交換はメートル単位・右手系Y-up（x＝東、y＝上、z＝南）。地理原点、元の座標系、変換を別途保持する。別のツールへ渡すときは軸変換を検査する。
- 建物ID、看板ID、アセット版、固定カメラ、共通の時間軸を維持する。外観の修正で道順や建物配置を勝手に変えない。
- 地形から高さ1.6m、35mm相当、通常歩行約1m/sを初期案とする。建物・道路・地形には共通の基準標高32mを使い、建物ごとに底を0へ揃えない。停止・振り向き・減速はカメラ計画に記録し、本編の尺は確認した経路長から決める。
- 季節・時刻・天候・露出・色管理は段階3で比較し、段階4の承認条件として固定する。「雨上がりの夕刻」等は候補であり、史実として扱わない。
- 元の制作データから同じシーンを再現できるようにする。人物や車両は、時代・接地・移動・遮蔽を検証できる範囲から増やす。
- 区間分割する場合は、同じ世界と時間軸の重複区間で接続を検査する。
- 再生成スクリプトは、ラウンドの出力先と日付を引数で受け取る。既定値で過去ラウンドの成果を上書きしない。`--help`だけでファイルを書き換えない。

### コードで作る原則

メッシュ・テクスチャ・シェーダー・看板・人物・小物は、すべてコードで生成する。外部の3Dモデル・画像テクスチャ・HDRは読み込まない。

- 生成は決定的にする。乱数は物のIDから作った固定シードを使い、同じ入力から毎回同じ世界ができるようにする。
- 地理の下敷き（PLATEAU・OpenStreetMap・地形）と、オープンライセンスのフォント（IPAゴシック等）は、出典を記録して使う。
- 第三者の素材や生成AIによる仕上げは、例外としてだけ使う。理由・出典・再配布条件を[アセット方針](ASSET_POLICY.md)に従って記録する。生成AIを使う場合も、建物の形、読める文字、人物の同一性、カメラ動線を維持する。

### 根拠の段階と看板の文字

資料で特定できない背景は、年代らしい一般的な形で補ってよい。生成物ごとに、次のいずれかの段階を記録する（three.jsでは`ctx.tag()`）。

| 段階 | 意味 | 例 |
| --- | --- | --- |
| `source-derived` | 出典のある形・位置・文字 | PLATEAUの敷地形状、地形、写真に写った門の文字 |
| `adopted-inferred` | 採用判断（`data/decisions/`）の推定値に従う形・寸法・色 | 門・劇場・噴水・街路灯の採用寸法と色 |
| `period-plausible-generic` | 資料で特定できない部分を、年代らしい一般的な形で補ったもの | 店構え・窓・看板の業種名・架空の店名・街灯・車・人物 |
| `placeholder` | 形状を検討するための仮の物 | 採用判断のない部分の仮の形 |

看板の文字は次のとおり扱う。

- 実在の店名・企業名・商標・ロゴ・映画の題名・俳優の顔は使わない。
- 一般的な業種名と、架空と明記した店名に限る。架空の店名は一覧として記録する。
- 例外は、採用判断で定めた固定文字（門・劇場名など）。
- 上演・上映の演目は、出典がない限り描かない。
- 推定した段階を、確認済みに格上げしない。

## 反復のしかた

各ラウンドは、次の順に実施する。ログは[ラウンド記録テンプレート](templates/ROUND_REPORT.md)を使い、`docs/rounds/`に残す。まだ実施していない検査は「未実施」、測定していない値は「未測定」と書く。

1. **比較条件を固定する。** 元コミット、対象シーン、カメラ、地点ごとの参考画、資料IDと年代、出力設定、光の設定、時間・費用の上限を記録する。描画手段の版とシード、利用可能ならモデル版とプロンプトも残す。
2. **修正対象を1〜3件に絞る。** ユーザーの具体的な指摘を優先し、次に最も重大な問題を選ぶ。例えば「曲がり角で劇場が早く見えすぎる」「入口看板の字が変わる」のように対象と場所を指定する。
3. **局所的に直してレンダーする。** 同じカメラの静止画、比較画像、必要な短い動画を作る。良くなった部分は維持する。
4. **比較・測定する。** 構図、光、色、素材、近景と遠景の密度を確認する。動画は通常速度の再生とコンタクトシートで経路全体を見て、疑わしい区間をコマ単位で調べる。フレーム差分等の自動検出は候補抽出として使い、人の目による確認を置き換えない。
5. **独立した批評を受ける。** 制作側の説明や自己採点を渡さず、[批評依頼テンプレート](templates/CRITIC_BRIEF.md)で新しい文脈の批評担当を使う。
   - 担当は「歴史・地理」と「映像・動き・音」の2系統に限る。画像領域またはタイムコード付きの指摘を得る。
   - 定義にない担当（技術・出典など）の判定で、この2系統を代用しない。
   - 実施できなかった系統は「未実施」と記録する。
   - 史実を理由に地物を加除・変更した場合は、歴史・地理の批評を受ける。
6. **修正・継続・資料調査を決める。** 致命的・重大な問題を解消してから段階を進める。史料不足なら追加調査または根拠を明示した推定採用を選ぶ。R03で認められた推定を再確認待ちへ戻さず、生成の反復だけで史実としての正しさを認定しない。
7. **結果を共有し記録する。** 比較画像、直した点、残る問題、次の修正対象を示す。承認を待つ間も、資料整理や別箇所の修正、数フレームのレンダーテストは続ける。

## 品質の判定基準

| 分野 | 合格の判断 | 検査方法 |
| --- | --- | --- |
| 歴史・地理と採用判断 | 原典に反する確定表現がなく、主経路・門・劇場の採用値が相互に整合する | 原典への対応表、俯瞰図、実写との比較。確認事実、推定値、反証、退けた代案を併記する |
| 縮尺 | 根拠のある寸法とモデルが対応する | 資料の測定精度を記録し、測れる箇所のみ誤差を測る。十分な精度がある箇所は差5%以内を初期目安にする |
| 見た目 | 6視点すべてで、下記6項目が2人の独立した映像批評担当からそれぞれ8点以上。重大な指摘とスロップ禁止項目の違反がない | 地点ごとの参考画との比較、近景と遠景の拡大、スロップ禁止リストの項目ごとの判定 |
| 空間の連続性 | 建物・看板・路面が突然変形・出現・消失しない | 共通の世界座標、固定カメラ、通常再生、曲がり角と遮蔽前後の重点検査 |
| 文字・人物・車 | 読める看板が変わらず、目立つ接地破綻・すり抜け・服装や同一性の不連続がない | 近景拡大、遮蔽前後と問題区間のコマ確認 |
| カメラ・時間 | 意図しない速度・露出・照明の急変、点滅、重複・欠落フレームがない | カメラ曲線とフレーム数の検査、通常再生とフレーム間の確認 |
| 音・出力 | 音の位置と距離が自然で、意図しない音割れ・無音・同期ずれがない。指定の解像度・fps・尺で再生できる | ファイル情報の検査、全編再生、ヘッドホン試聴、音源の出典確認 |

「致命的」は経路や建物の取り違え、再生不能など目標を崩す問題。「重大」は通常の視聴で気づく破綻。「軽微」は拡大すると分かる局所的な差。批評結果は合格・要修正・資料不足に分け、根拠不足を合格へ丸めない。資料がない背景の細部は、上記の根拠の段階を付けて推定で補う。

### 見た目の採点

映像批評担当は、地点ごとに次の6項目を10点満点で採点する。

1. 構図の自然さ（参考画がある地点はその構図と比べる）
2. 光と色（グレーに沈みすぎず、彩度過多でもない）
3. 素材の実在感（汚れ・雨だれ・錆・ムラ）
4. 近景・中景・遠景の密度
5. 看板の読みやすさと年代の合い方
6. スロップがないこと

静止画の合格は、全項目8点以上、重大な指摘なし、スロップ禁止項目の違反なし。これを2人の独立した批評担当がそれぞれ満たすこととする。合格したら、ユーザーに静止画を見せて承認を得る。動画（段階5・6）は、その承認の後に作る。

点数は見た目の主観評価であり、段階を進めるための見た目の判定にだけ使う。史実の一致率や、重大な欠陥がないことの証明には使わない。寸法・フレーム数等の実測値とは分けて記録する。「99%正確」とは認定しない。

### 禁止するスロップ

批評担当は、静止画ごとに各項目を「違反なし／違反あり」で判定する。

1. 発光・ブルーム・霞・ぼかしで形状不足を隠すこと。昼間に強く光るネオン。レンズフレア。過度な色被り。
2. 意味をなさない日本語、偽の漢字、中国語の簡体字、ラテン文字の埋め草。縦書きで長音記号「ー」を横向きのまま並べること。
3. 同じ外観・看板・人物が隣り合って繰り返されること。継ぎ目が見える素材の繰り返し。
4. 汚れのないCGらしい清潔さ。全体がグレーに沈むこと。全体の彩度過多。
5. 浮いている物、接地の影がない物、建物を貫通する物。
6. 年代に合わない物：LED、液晶画面、現代の車、コンビニの看板、現代の道路標示、現代の自販機の形、樹脂製の現代的な看板、現代の書体。
7. 実在のブランド・ロゴ。画面上の説明文字（地点ラベルなど）。
8. フレームごとに変わる文字・物・人物（動画）。

## 進捗・費用・確認の節目

- 最低8時間などの待機時間を完成条件にしない。初期の作業単位は60〜90分を目安に区切り、成果・問題・実際の所要時間を記録する。長いレンダーは先に数フレームで速度と費用を測る。
- 比較候補は最初は最大3案を目安にし、採用案を深く直す。各ラウンドの生成回数、使用ツール、実費または未確定額、残予算を記録する。利用枠を使い切ること自体を目標にしない。
- 有料APIや外部GPUの予算は未設定。費用が発生する処理の前に、小さな測定結果から必要量と見積もりを具体化する。予算待ちでも、既に認められた資料調査やローカル作業は進める。
- ユーザーがまとめて判断する節目は、6視点の画づくりと15秒試写の歩行感。既存の承認を引き継ぎ、同じ条件を繰り返し確認しない。承認前に長時間・高額な最終出力を始めない。
- 通常速度での再生とヘッドホンでの試聴のうち、エージェントが実施できない検査は、ユーザーに依頼する項目として記録する。担当者のない検査を合格扱いにしない。
- GitHubへの制作データ・手順の蓄積は継続する。リポジトリは公開とする（2026-11-02）。非公開のリンク・認証情報・アカウント識別子は置かない。映像のSNS投稿や外部公開は、制作完了と区別する。

## 出典記録とファイル管理

- 公開するデータ・画像・モデルには、すべて隣に`*.asset.json`を置く。出典、ライセンス、再配布条件、出典年と復元年、確実性を書く。
- 対象は、`scenes/`、`data/`（`data/raw/`を除く）、`docs/previews/`、`assets/shared/`の、コード・文書以外のファイル。
- 出典記録が不要な設定ファイルは、テストの除外一覧に理由とともに載せる。
- 検証コマンドは`python3 -m unittest discover -s tests`。出典記録のないファイルや必須項目の欠落を検出できるよう、テストを拡張する（未対応）。
- `.gitattributes`に挙げたバイナリ形式は、Git LFSで管理する。新しい種類のバイナリ（外部バッファの`.bin`、動画、音声、高解像度テクスチャ等）を追加する前に、LFSの対象へ加える。
- 既存の`.gltf`は、バッファを埋め込んだ1行のファイルとして通常のGitに入っている。今後は、GLBをLFSで管理するか、`.gltf`と外部`.bin`に分ける。履歴の書き換えはしない。
- コード生成の静止画（`docs/previews/`）は、代表的なものだけを公開する。描画出力の全体は、gitignore済みの`renders/`に置く。

## 採用版の再生成と仕上げ

初回取り込みは[第1ラウンド](DATA_INTAKE_R01.md)、カメラ・地形・出典の改訂は[外部レビュー対応](rounds/shinjuku-kabukicho-1976-r01-review-fix.md)、制作採用の完了は[R03](rounds/shinjuku-kabukicho-1976-r03-completion.md)に記録した。

再開時は[採用版の案内](RECONSTRUCTION_ADOPTED_1976.md)、`data/decisions/`、地物の分類、採用モデルと歩行軌道を読む。新しい史料が見つかった場合は、該当する採用判断を更新し、モデル・文字メッシュ・歩行軌道・メタデータ・検査を同じ手順で再生成する。推定値を変える場合も、現代の元データと承認済みカラー参考画9枚は維持する。

次の映像仕上げでは、採用した共通の世界を使い、入口近景の素材・汚れ・反射、全経路の密度、連続歩行の見え方、人物・車・環境音を検査する。静止画と疎な歩行フレームの検査結果を、長編動画全体の合格へ置き換えない。

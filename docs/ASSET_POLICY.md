# アセットとデータの扱い

## 単位と地理参照

- シーン交換用モデルは1単位=1m、右手系Y-upを基準とする。
- 地理参照用の原点、元の座標参照系、変換方法はシーンに記録する。未確定座標は`null`のまま扱う。
- Blender等の制作座標系からの変換は、書き出し設定とともに記録する。
- 現代の地図・建物データと、目標年代の復元形状を区別する。

## 公開する各アセットの記録

モデル、地図、テクスチャ、画像などを追加するときは、隣接する`*.asset.json`に以下を記録する。

- ID、リポジトリ内パス、アセット種別
- 配布元・著作者・原典URL・取得日
- 適用ライセンスとそのURL、必要なクレジット
- 原資料の年代と、再構成の目標年代
- 加工方法と依存するアセットID
- SHA-256、形式、単位、座標系
- 地理の確認状況：`verified` / `approximate` / `unverified`
- 歴史考証の確認状況と、推定・演出で補った範囲
- 再配布条件の確認結果

コードのMITライセンスが、第三者データや写真へ自動的に適用されるわけではない。個別の利用条件を記録し、確認を終えたアセットを公開する。確認前の資料はURLとメタデータを記録し、原本を公開リポジトリへコピーしない。

## 保管

- `data/sources.json`：配布元と資料の台帳。
- `data/raw/`：ローカルで取得した原本。Git対象外。
- `scenes/<ward>/<district>/<year>/models/`：加工済みのシーン用モデル。
- 同じシーンの`textures/`、`cameras/`：対応する素材と動線。
- `assets/shared/`：地区をまたいで再利用するアセット。
- `renders/`：生成動画・中間レンダー。Git対象外。

`.blend`、`.glb`等の制作バイナリはGit LFSで扱う想定。実ファイルを追加する作業環境では、先にGit LFSを導入する。配布元の大量データは取得手順とチェックサムを記録して再取得できるようにする。
